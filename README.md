# PunktScan

[![Tests and build](https://github.com/OlYermakov/PunktScan/actions/workflows/ci.yml/badge.svg)](https://github.com/OlYermakov/PunktScan/actions/workflows/ci.yml)

Застосунок українською для перетворення фотографій таблиць координат у **Leica GSI-16** для подальшого імпорту в CAPLAN або геодезичне обладнання.

Фото → виправлення перспективи → розпізнавання → звіряння точок → GSI або CSV.

Усі обчислення та розпізнавання виконуються у браузері. Сервер, обліковий запис та API-ключ не потрібні. Фото користувача не надсилаються на сервер. Модуль Tesseract та мовна модель входять до збірки; зовнішні CDN і аналітика не використовуються.

## Запуск на комп’ютері

Потрібні Node.js 22 або новіший та npm. Для `npm run test:e2e` один раз виконай `npx playwright install chromium`. Якщо браузер уже встановлено окремо, шлях до нього можна передати змінною `PW_CHROMIUM`. У GitHub Actions використовується Node.js 24 із `.nvmrc`.

```sh
npm ci
npm run lint
npm test
npm run build
npm run check:build
npm run test:e2e
npm run preview
```

Відкрий **http://localhost:4173/PunktScan/**. Локальний сервер імітує адресу GitHub Pages із підкаталогом. Не відкривай `index.html` подвійним натисканням: модуль розпізнавання та Service Worker потребують HTTP/HTTPS. Для іншого порту: `PORT=8080 npm run preview` у Linux/macOS або `$env:PORT=8080; npm run preview` у PowerShell.

## GitHub Pages

Код готовий для адреси `https://olyermakov.github.io/PunktScan/`. Це очікувана адреса після ввімкнення Pages, а не підтвердження чинної публікації.

1. У репозиторії відкрий **Settings → Pages**.
2. У **Build and deployment → Source** обери **GitHub Actions**.
3. Кожна зміна в `main` публікується автоматично. Також можна запустити вручну: **Actions → Publish GitHub Pages → Run workflow**.
4. Після успішного завдання `deploy` відкрий посилання з його результату.

Workflow `Tests and build` перевіряє зміни в `main` і pull request: unit-тести, збірку, ресурси та наскрізні тести в браузері, включно з реальним розпізнаванням прикладу. Workflow `Publish GitHub Pages` виконує ті самі перевірки (без повільного тесту розпізнавання) і лише потім публікує `dist/`. Секрети та платні служби не потрібні.

Зібраний `dist/` також можна розмістити на будь-якому статичному HTTPS-хостингу. Шляхи, значки, маніфест і модуль розпізнавання працюють як у корені сайту, так і в підкаталозі.

## Робота з координатами

1. Додай до 20 зображень, не більше 20 МіБ кожне. HEIC залежить від підтримки браузера; JPEG і PNG надійніші.
2. Перевір рамку таблиці. За потреби поверни зображення або поправ її чотири кути.
3. Перевір порядок стовпців: **Rechtswert = E**, **Hochwert = N**. Автоматичне визначення заголовків не замінює звіряння.
4. Запусти розпізнавання. Значення можна виправляти в таблиці або вставити текстом.
5. Відкрий кожну точку та звір назву й координати з фрагментом початкового зображення. Перевір також кількість рядків: розпізнавання може пропустити рядок.
6. Завантаж `.GSI`, `.CSV` або збережи весь проєкт `.json` разом із фотографіями.

На смартфоні кожна точка показується карткою з E, N і H без прокручування вбік. Під час звіряння над кожним полем показано відповідну клітинку оригінального фото. Цифрова клавіатура iPhone не має мінуса, тому біля координат є кнопка «±». Під час розпізнавання екран не гасне (якщо браузер підтримує Wake Lock); не перемикайся на інші застосунки до завершення.

Розпізнавання може помилитися навіть у числі з правильним форматом. Особливо складні похилі фотографії екрана, муар, вузькі креслярські шрифти та дрібні десяткові крапки. Невпевнені прочитання позначаються. Експорт доступний після звіряння всіх точок; редагування скасовує звіряння зміненої точки.

## Правила GSI

| Поле           | Правило                                                                           |
| -------------- | --------------------------------------------------------------------------------- |
| Назва точки    | Латинські літери, цифри, `_`, `.`, `-`; максимум 16 символів; пробіли вилучаються |
| E / Rechtswert | Слово WI 81, метри на вході, цілі міліметри у файлі                               |
| N / Hochwert   | Слово WI 82, метри на вході, цілі міліметри у файлі                               |
| H / Höhe       | Слово WI 83 лише за наявності висоти; явно введений нуль зберігається             |
| Точність       | До 3 десяткових знаків, без автоматичного округлення                              |
| Формат         | GSI-16, ASCII, CRLF, 16 символів даних, `*` на початку блоку                      |

Відсутні або некоректні координати, незвірені точки, повтори назв і зайві десяткові знаки блокують експорт. Порівняння назв консервативне: регістр і початкові нулі не розрізняються. Перетворення в міліметри використовує `BigInt`, без похибки двійкової арифметики. Система координат не визначається та не перераховується. CSV має роздільник `;`, десяткову кому й UTF-8 BOM.

CAPLAN у цьому середовищі недоступний. Перед використанням у роботі перевір імпорт контрольного файлу у своїй версії програми, порядок E/N, назви точок та висоти.

## Офлайн і збереження

- Чернетка зберігається в IndexedDB поточного браузера. Це одна поточна чернетка, а не архів проєктів.
- Кнопка **«Робота без інтернету»** завантажує приблизно 24 МБ ресурсів. Після завершення відкрий застосунок без мережі та перевір його на своєму пристрої.
- На iPhone відкрий опубліковану HTTPS-адресу в Safari та обери **«Поділитися → На початковий екран»**.
- Після публікації нової версії відкритий застосунок показує «Доступна нова версія» та перезавантажується лише після натискання «Оновити», зберігши чернетку.
- Браузер або операційна система можуть видалити локальні дані. Зберігай важливі проєкти файлами `.json`.
- Перехід з іншого домену не переносить чернетку автоматично. Збережи JSON на старому сайті та відкрий його на новому; імпорт вимагатиме повторного звіряння точок.

## Приклади та перевірки

`src/demo-1.jpg` і `src/demo-2.jpg` — створені для демонстрації таблиці з **вигаданими координатами**. Фото реального робочого об’єкта в цей публічний репозиторій не включені. Кнопка прикладу запускає справжнє розпізнавання зображень, готові значення у застосунок не підставляються. Еталонні CSV та GSI в `examples/` призначені лише для звіряння.

Тести перевіряють точні міліметри, знаки, десяткові роздільники, відсутню й нульову висоту, відмову від округлення, повтори назв, перевірку проєктів, геометрію рамки та серіалізацію 14 навчальних точок. `test:e2e` у справжньому Chromium відкриває зібраний застосунок за адресою `/PunktScan/`, вставляє еталонну таблицю, звіряє всі точки й порівнює завантажений GSI з `examples/demo-reference.GSI` байт у байт; з `E2E_OCR=1` також розпізнає обидва фото прикладу. `check:build` перевіряє ресурси та область PWA для `/` і `/PunktScan/`, включно з OCR-файлами й офлайн-пакетом.

Початкова версія пройшла перевірку реального розпізнавання двох фотографій: 14 рядків, 27 із 28 координат прочитані правильно без редагування; помилкове значення із зайвим десятковим знаком заблокувало експорт. Після звіряння завантажений GSI точно збігся з контрольним файлом. Цей результат описує конкретну перевірку, не гарантує таку саму точність інших фото. Перевірка імпорту в CAPLAN і робота на фізичному iPhone залишаються окремими польовими перевірками.

## Код

| Файл                 | Призначення                                                         |
| -------------------- | ------------------------------------------------------------------- |
| `src/core.js`        | Перевірка даних, точні числа, GSI/CSV, текстовий імпорт             |
| `src/imaging.js`     | Рамка, перспектива, клітинки, підготовка зображення                 |
| `src/app.js`         | Запуск застосунку та обробники подій                                |
| `src/state.js`       | Спільний стан: проєкт, вибране фото, фільтри                        |
| `src/render.js`      | Відображення джерел, фото й таблиці точок; скасування змін          |
| `src/photos.js`      | Додавання фото                                                      |
| `src/ocr.js`         | Розпізнавання Tesseract по клітинках і рядках                       |
| `src/dialogs.js`     | Звіряння точок, вставлення тексту, експорт, проєкти, офлайн         |
| `src/storage.js`     | Чернетка в IndexedDB                                                |
| `src/dom.js`         | Допоміжні функції DOM, canvas і завантаження файлів                 |
| `src/sw.js`          | Кеш застосунку та офлайн-ресурси                                    |
| `scripts/`           | Збірка, перевірка ресурсів, локальний перегляд                      |
| `tests/`             | Unit-тести (`npm test`) і наскрізні тести в браузері (`tests/e2e/`) |
| `.github/workflows/` | Автоматичні перевірки та публікація Pages                           |

Код форматує Prettier (`npm run format`) і перевіряє ESLint (`npm run lint`, також у CI). Dependabot щомісяця пропонує оновлення npm-залежностей і GitHub Actions. Новий модуль у `src/` автоматично потрапляє до кешу Service Worker.

Версію кешу не потрібно змінювати вручну: `npm run build` рахує хеш вмісту `src/` і `package-lock.json` та підставляє його замість `__BUILD__` в `index.html` і всіх JS-модулях. `check:build` перевіряє, що всі посилання мають однакову версію. Ліцензії сторонніх компонентів потрапляють у `dist/licenses.txt`.
