# PunktScan

[![Tests and build](https://github.com/OlYermakov/PunktScan/actions/workflows/ci.yml/badge.svg)](https://github.com/OlYermakov/PunktScan/actions/workflows/ci.yml)

Застосунок для перетворення фотографій таблиць координат у **Leica GSI-16** для подальшого імпорту в CAPLAN або геодезичне обладнання.

Мови інтерфейсу: німецька (за замовчуванням), англійська, французька, італійська, іспанська, польська та українська. Мову змінює перемикач із глобусом угорі; вибір зберігається в браузері.

Фото → виправлення перспективи → розпізнавання → звіряння точок → GSI або CSV.

Усі обчислення та розпізнавання виконуються у браузері. Сервер, обліковий запис та API-ключ не потрібні. Фото користувача не надсилаються на сервер. Обидва рушії розпізнавання входять до збірки: Tesseract з англійською моделлю та PaddleOCR (модель PP-OCRv6 tiny на ONNX Runtime Web); зовнішні CDN і аналітика не використовуються.

## Запуск на комп’ютері

Потрібні Node.js 22 або новіший та npm. Для `npm run test:e2e` один раз виконай `npx playwright install chromium`. Якщо браузер уже встановлено окремо, шлях до нього можна передати змінною `PW_CHROMIUM`. У GitHub Actions використовується Node.js 24 із `.nvmrc`.

```sh
npm ci
npm run lint
npm test
npm run build
npm run check:build
npm run test:e2e
npm run preview
```

Відкрий **http://localhost:4173/PunktScan/**. Локальний сервер імітує адресу GitHub Pages із підкаталогом. Не відкривай `index.html` подвійним натисканням: модуль розпізнавання та Service Worker потребують HTTP/HTTPS. Для іншого порту: `PORT=8080 npm run preview` у Linux/macOS або `$env:PORT=8080; npm run preview` у PowerShell.

## GitHub Pages

Код готовий для адреси `https://olyermakov.github.io/PunktScan/`. Це очікувана адреса після ввімкнення Pages, а не підтвердження чинної публікації.

1. У репозиторії відкрий **Settings → Pages**.
2. У **Build and deployment → Source** обери **GitHub Actions**.
3. Кожна зміна в `main` публікується автоматично. Також можна запустити вручну: **Actions → Publish GitHub Pages → Run workflow**.
4. Після успішного завдання `deploy` відкрий посилання з його результату.

Workflow `Tests and build` перевіряє зміни в `main` і pull request: unit-тести, збірку, ресурси та наскрізні тести в браузері, включно з реальним розпізнаванням прикладу. Workflow `Publish GitHub Pages` виконує ті самі перевірки (без повільного тесту розпізнавання) і лише потім публікує `dist/`. Секрети та платні служби не потрібні.

Зібраний `dist/` також можна розмістити на будь-якому статичному HTTPS-хостингу. Шляхи, значки, маніфест і модуль розпізнавання працюють як у корені сайту, так і в підкаталозі.

## Робота з координатами

1. Додай до 20 зображень, не більше 20 МіБ кожне. HEIC залежить від підтримки браузера; JPEG і PNG надійніші.
2. Перевір рамку таблиці. За потреби поверни зображення або поправ її чотири кути: торкнись біля кута й веди палець — кут рухається разом із ним, а лупа над пальцем показує його збільшеним.
3. Запусти розпізнавання. Порядок стовпців (**Rechtswert = E**, **Hochwert = N**), очищення муару й автоматична рамка сховані в «Додаткових налаштуваннях»: зазвичай їх чіпати не треба. Значення можна виправляти в таблиці або вставити текстом.
4. Подивись результат на фото (вкладка «Результат», відкривається сама після розпізнавання): кожне прочитане значення обведене зеленим (впевнено або вже звірено), жовтим (перевір) чи червоним (помилка). Рядок без рамок — пропущений рядок. Торкання значення відкриває картку цієї точки. На комп’ютері фото й таблиця стоять поруч: наведення на рядок таблиці підсвічує його клітинки на фото, і навпаки.
5. Звір точки. Звіряння відкривається карткою: над кожним значенням фрагмент фото, під ним великі цифри; символи, розпізнані з сумнівом (низька впевненість або інший прохід прочитав інакше), підсвічені жовтим. «✓ Правильно» або свайп вправо підтверджує точку, свайп вліво відкладає, «Виправити» відкриває поля. Спершу йдуть точки з помилками, потім сумнівні; коли лишаються лише розпізнані без сумнівів, вони показуються разом на одному екрані з фрагментами фото й підтверджуються однією кнопкою. Перевір також кількість рядків: розпізнавання може пропустити рядок.
6. Завантаж `.GSI`, `.CSV` або збережи весь проєкт `.json` разом із фотографіями. На телефоні у вікні експорту є «Надіслати…»: GSI чи CSV одразу йде через системне меню «Поділитися» в пошту, AirDrop, месенджер або на диск. Якщо надіслати не вдалося, файл зберігається звичайним способом.

Над роботою показано кроки «Фото → Рамка → Звіряння → Файл». На смартфоні це три окремі екрани — «Фото» (джерела, рамка, розпізнавання), «Звіряння» (фото з результатом і точки) та «Файл» (підсумок: скільки точок, з висотою чи ні, одиниця GSI); застосунок сам переходить на наступний, а торкання кроку повертає до попереднього. Унизу екрана завжди є кнопка наступного кроку: додати фото, розпізнати, звірити наступну точку (спершу ті, що з помилками) або завантажити GSI. Рідкісні дії з проєктом сховані в меню «⋯». На смартфоні кожна точка показується карткою з E, N і H без прокручування вбік. Під час звіряння над кожним полем показано відповідну клітинку оригінального фото. Цифрова клавіатура iPhone не має мінуса, тому біля координат є кнопка «±». Під час розпізнавання екран не гасне (якщо браузер підтримує Wake Lock); не перемикайся на інші застосунки до завершення.

Застосунок має одну світлу тему в стилі **Liquid Glass**: напівпрозорі «скляні» панелі розмивають м'які плями бірюзового, помаранчевого й лаймового на пісочному тлі, мають світлий відблиск по краю й великі заокруглення, а кнопки — капсули. Шапка й бічна панель — темне бірюзове скло. На телефоні нижня кнопка кроку плаває скляною капсулою. Якщо в системі ввімкнено «Зменшити прозорість», панелі стають непрозорими.

Палітра: нічний `#0A0F14` (текст), глибокий бірюзовий `#0F3D3E` (шапка, бічна панель, іконка), бірюзовий `#2E6F73` (головна дія), пісочний `#EADCC8` (тло), лаймовий `#BCF34E` (акцент на темному бірюзовому: поточний крок, «+», індикатор, кути на іконці) і помаранчевий `#C6601F` (акцент на світлому й на фото: рамка й кути, лупа, рамка фокуса, крапка на іконці). Кожен колір застосунку — роль із `:root` на початку `style.css`: нейтральні `--canvas`, `--surface`, `--surface-soft`, `--line`/`--line-strong`, `--ink`/`--ink-soft`/`--muted`/`--faint`; фірмові `--brand-*`, `--primary`, `--accent`, `--accent-warm`, `--brand-text`; статуси `--ok` (зелене — звірено або впевнено), `--warn` (жовте — перевір), `--err` (червоне — помилка) з варіантами `-soft`, `-line` і `-strong`. Скло складається з цих ролей (`--glass`, `--glass-edge` тощо в кінці `style.css`). Межі кнопок, полів і перемикачів мають окрему роль `--control-line` з контрастом щонайменше 3 : 1 і на картках, і на тлі (WCAG 1.4.11); картки щільні (90 % білого) з видимою межею й тінню, щоб не зливатися з пісочним тлом. Поза палітрою колір не задається. `tests/palette.test.mjs` перевіряє це й контраст кожної пари «текст — тло» (не нижче 4,5 : 1), а наскрізний тест — контраст кожного видимого тексту на склі.

Таблиці з чіткою сіткою читаються по клітинках. Лінії сітки шукаються спершу як темні рядки й стовпці пікселів; на фото екрана зблизька муар дає десятки смуг, схожих на лінії, а цифри «1» одна під одною — теж. Тоді застосунок шукає лінії вдруге: розмиває зображення впоперек лінії (дрібні смуги стають рівномірно сірими) і вимагає однієї довгої темної ділянки, якої цифри в окремих рядках не утворюють. Таблиці без зовнішніх рамок, зі значеннями в окремих рамочках (експорт із CAD), а також трохи похилі чи обрізані фото паперу читаються за положенням слів: застосунок групує числа в колонки й рядки, враховуючи нахил, а потім читає кожне значення окремо. Якщо автоматична рамка обрізала частину таблиці, застосунок також пробує все фото. Коли прочитане значення має іншу форму, ніж решта колонки (наприклад, без крапки), застосунок може взяти інший прохід розпізнавання тієї ж клітинки; така клітинка залишається позначеною для звіряння. Якщо крапку не видно в жодному проході, а решта колонки має один формат (наприклад, `3415xxx.xxx`) і значення має рівно стільки ж цифр і той самий початок, крапка ставиться на місце, де вона в колонці; цифри не змінюються, і значення лишається позначеним. Очищення муару розмиває зображення перед підсиленням контрасту; якщо після нього зникає майже весь текст (тонкі креслярські штрихи в експорті з CAD чи на скриншоті), застосунок читає необроблене зображення.

Порядок E/N визначається насамперед за самими числами: Rechtswert починається з номера зони (2–4 у Гаусса — Крюгера, 32/33 в UTM із зоною), Hochwert — семизначне число від 5 000 000. Якщо чисел недостатньо, використовуються заголовки, а якщо немає й їх — E, N. Коли заголовки суперечать числам (наприклад, «Hoch» над колонкою Rechtswert), застосунок обирає порядок за числами й повідомляє про це. Явно вибраний порядок завжди має пріоритет. Якщо автоматична рамка могла обрізати таблицю, застосунок перевіряє все фото й бере його, коли там більше рядків; рамку, виставлену вручну, не змінює. Фото лише однієї колонки чисел точок не дає: застосунок попросить сфотографувати всю таблицю.

**Друге розпізнавання.** Після Tesseract кожну клітинку ще раз читає PaddleOCR (PP-OCRv6 tiny, 4,5 МБ, ліцензія Apache 2.0) в окремому Web Worker. Правило поєднання підібране на справжніх фото та погіршених копіях (половинна роздільність, розмиття, нахил, шум, стиснення):

- обидва рушії прочитали однаково, значення має правильний формат і форму своєї колонки, а Tesseract був хоча б помірно впевнений — значення вважається підтвердженим і позначка сумніву знімається;
- прочитання різні — береться значення правильного формату, спершу PaddleOCR (він точніший), поле лишається жовтим, а символи, якими прочитання відрізняються, підсвічуються.

На 10 справжніх фото це дало 351 правильне поле із 355, непомічених помилок — 0. Якщо обидва рушії прочитали клітинку по-різному, перевага в другого, крім випадку, коли лише прочитання Tesseract має форму решти колонки (DT202 серед DT2xx проти 6166 з муарної клітинки); форма колонки рахується за прочитаннями обох рушіїв, тож повторювана помилка одного з них (9 замість кожної початкової 5) не переважить. Шматок лінії сітки на краю клітинки, прочитаний як дужка чи риска, відкидається. Без форми колонки й упевненості обидва рушії однаково «підтверджували» висоти, що через загублену колонку потрапили в Rechtswert; тепер такі колонки ловить перевірка порядку величини. Друге розпізнавання додає 1–2 с на фото на комп’ютері; його можна вимкнути в «Додаткових налаштуваннях». Якщо браузер не може його запустити, лишається результат Tesseract.

Розпізнавання може помилитися навіть у числі з правильним форматом. Частину таких помилок застосунок ловить за геометрією та назвами (`plausibility` у `core.js`), позначає поле жовтим із поясненням і ставить точку на звіряння раніше за інші:

- точка лежить далеко від усіх інших (за медіаною й найближчою сусідньою; окрема група точок, наприклад інша частина об’єкта, не позначається) — підсвічується вісь, що зсунулася;
- висота сильно відрізняється від інших;
- E і N однієї точки відрізняються більш ніж у сто разів (у масштабі Гаусса — Крюгера чи UTM), або ціла колонка має інший масштаб — найімовірніше, висота чи інше число потрапило в колонку координат;
- «висота» велика, як координата;
- значення має інші початкові цифри (з точністю до 10 км) чи іншу кількість цифр, ніж три чверті колонки, або назва не відповідає шаблону трьох чвертей назв;
- назва випадає з ряду сусідів (F-1.2, **F-13**, F-1.4 → «очікувано F-1.3»);
- у ряду назв пропущено номер (P4, **P6**) — можливо, рядок таблиці не розпізнано.

Ці перевірки лише попереджають і не блокують експорт. На семи справжніх таблицях вони не дали жодної хибної тривоги. В імітації, де в справжніх таблицях замінювали одну цифру координати, хибну цифру в тисячах метрів і вище ловлять завжди, у сотнях — у ~90 % випадків, у десятках — приблизно в половині. Помилку в одиницях метрів і в дробовій частині видно лише при звірянні з фото.

«Схема точок» показує E і N в одному масштабі. Її можна зумувати коліщатком миші, двома пальцями, подвійним натисканням або кнопками +/−, рухати перетягуванням чи стрілками; ⤢ або 0 повертає весь об’єкт. Точки й підписи не збільшуються, тож близькі точки розходяться; сітка й масштабна лінійка (1/2/5 × 10ⁿ м) змінюються разом із зумом. Натискання на точку відкриває її картку звіряння.

Для розпізнавання особливо складні похилі фотографії екрана, муар, вузькі креслярські шрифти та дрібні десяткові крапки. Невпевнені прочитання позначаються. Експорт доступний після звіряння всіх точок; редагування скасовує звіряння зміненої точки.

## Правила GSI

| Поле           | Правило                                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Назва точки    | Латинські літери, цифри, `_`, `.`, `-`; максимум 16 символів; пробіли вилучаються                                                                                                                            |
| E / Rechtswert | Слово WI 81, метри на вході, цілі міліметри (або 0,1 мм) у файлі                                                                                                                                             |
| N / Hochwert   | Слово WI 82, метри на вході, цілі міліметри (або 0,1 мм) у файлі                                                                                                                                             |
| H / Höhe       | Слово WI 83 лише за наявності висоти; явно введений нуль зберігається                                                                                                                                        |
| Точність       | До 4 десяткових знаків, без автоматичного округлення. Якщо хоч одне значення має 4 знаки, увесь файл пишеться в одиницях 0,1 мм (код одиниці `6`, слова `81..06`), інакше — у міліметрах (код `0`, `81..00`) |
| Формат         | GSI-16, ASCII, CRLF, 16 символів даних, `*` на початку блоку                                                                                                                                                 |

Відсутні або некоректні координати, незвірені точки, повтори назв і зайві десяткові знаки блокують експорт. Порівняння назв консервативне: регістр і початкові нулі не розрізняються. Перетворення в міліметри та 0,1 мм використовує `BigInt`, без похибки двійкової арифметики. Система координат не визначається та не перераховується. CSV має роздільник `;`, десяткову кому й UTF-8 BOM.

Імпорт файлів в одиницях 0,1 мм у CAPLAN ще не перевірявся: перевір перший такий файл окремо.

CAPLAN у цьому середовищі недоступний. Перед використанням у роботі перевір імпорт контрольного файлу у своїй версії програми, порядок E/N, назви точок та висоти.

## Офлайн і збереження

- Усі об’єкти зберігаються в IndexedDB поточного браузера разом із фото. «Нове» відкриває порожній об’єкт, а попередній лишається в списку **«Мої об’єкти»** (бічна панель або меню «⋯» на смартфоні). На стартовому екрані показано «Нещодавні»: мініатюра, назва, дата, кількість точок і скільки з них звірено. Відкритий із файлу `.json` проєкт стає новим об’єктом і не замінює поточний. Порожні об’єкти до списку не потрапляють. Чернетка попередніх версій сама переноситься в список.
- Кнопка **«Робота без інтернету»** завантажує приблизно 44 МБ ресурсів (з них близько 20 МБ — другий рушій розпізнавання). Після завершення відкрий застосунок без мережі та перевір його на своєму пристрої.
- На iPhone відкрий опубліковану HTTPS-адресу в Safari та обери **«Поділитися → На початковий екран»**.
- Після публікації нової версії відкритий застосунок показує «Доступна нова версія» та перезавантажується лише після натискання «Оновити», зберігши чернетку.
- Браузер або операційна система можуть видалити локальні дані. Зберігай важливі проєкти файлами `.json`.
- Перехід з іншого домену не переносить чернетку автоматично. Збережи JSON на старому сайті та відкрий його на новому; імпорт вимагатиме повторного звіряння точок.

## Приклади та перевірки

`tests/fixtures/table-1.jpg` і `table-2.jpg` — тестові таблиці з **вигаданими координатами**; у застосунок вони не входять. `tests/fixtures/real/` — справжні фото з роботи (екран під кутом, таблиці CAD із рамочками навколо значень і 4 знаками після крапки, експорт CAD тонким креслярським шрифтом на сірому тлі, папір на вулиці) з правильними значеннями в `expected.json`; додані з дозволу власника. Тест `real field photos` (з `E2E_OCR=1`) вимагає, щоб жодне неправильно прочитане значення не залишалося без позначки, а точність не падала нижче 273 із 313 полів (на момент останнього доповнення — 283 із 313). Еталонні `examples/test-points.csv` і `examples/test-reference.GSI` містять правильні значення для цих таблиць.

Тести перевіряють точні міліметри, знаки, десяткові роздільники, відсутню й нульову висоту, відмову від округлення, повтори назв, перевірку проєктів, геометрію рамки та серіалізацію 14 навчальних точок. `test:e2e` у справжньому Chromium відкриває зібраний застосунок за адресою `/PunktScan/`, вставляє еталонну таблицю, звіряє всі точки й порівнює завантажений GSI з `examples/test-reference.GSI` байт у байт; з `E2E_OCR=1` також розпізнає обидва тестові фото. Перевіряються також перемикання мов і ширина сторінки 320 px для кожної мови. `tests/i18n.test.mjs` стежить, щоб усі мови мали однакові ключі, підстановки, розмітку й потрібні форми множини. `check:build` перевіряє ресурси та область PWA для `/` і `/PunktScan/`, включно з OCR-файлами й офлайн-пакетом.

Початкова версія пройшла перевірку реального розпізнавання двох фотографій: 14 рядків, 27 із 28 координат прочитані правильно без редагування; помилкове значення із зайвим десятковим знаком заблокувало експорт. Після звіряння завантажений GSI точно збігся з контрольним файлом. Цей результат описує конкретну перевірку, не гарантує таку саму точність інших фото. Перевірка імпорту в CAPLAN і робота на фізичному iPhone залишаються окремими польовими перевірками.

Новий текст інтерфейсу додавай ключем у `src/lang-de.js` і в усі інші словники; тест не пропустить відсутній переклад.

Код форматує Prettier (`npm run format`) і перевіряє ESLint (`npm run lint`, також у CI). Dependabot щомісяця пропонує оновлення npm-залежностей і GitHub Actions. Новий модуль у `src/` автоматично потрапляє до кешу Service Worker.

Версію кешу не потрібно змінювати вручну: `npm run build` рахує хеш вмісту `src/` і `package-lock.json` та підставляє його замість `__BUILD__` в `index.html` і всіх JS-модулях. `check:build` перевіряє, що всі посилання мають однакову версію. Ліцензії сторонніх компонентів потрапляють у `dist/licenses.txt`.
